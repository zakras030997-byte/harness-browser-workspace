# Harness Use · Browser & Computer Workspace

Open-source плагин для **официального DeepSeek Harness Desktop 0.2.2-rc.3 на macOS**. Chrome и изолированный Chromium, живые карточки в чате, повторное использование проверенных запросов, ограниченная память сайтов и отдельный помощник Computer Use.

Установщик **не создаёт копию Harness, не меняет app.asar, подпись, bundle ID или штатный обновлятор**. Старое управление нативным Electron-окном из 0.2.x исключено: оно требовало переподписанного приложения. Вместо него доступны изолированный Chromium с просмотром и внешний Chrome.

## Установка или обновление

1. Установите официальный Harness из [источника DeepSeek](https://harness.deepseek.com/), один раз запустите и настройте его, затем завершите через Command-Q.
2. Скачайте `Harness-Use-0.3.1-macOS.zip` и `SHA256SUMS` из [Releases](https://github.com/zakras030997-byte/harness-browser-workspace/releases). Распакуйте ZIP.
3. Запустите `Install.command`. Плагин устанавливается в существующий desktop-профиль. Текущие модели, аккаунты, проекты, чаты и несвязанные плагины сохраняются. Первый запуск скачивает закреплённые зависимости и Chromium, поэтому нужен Интернет. Отдельный Node.js не требуется: используется runtime официального Harness.
4. Откройте исходный официальный Harness. Попросите «Включи изолированный браузер, открой example.com и покажи миниатюру».

Если приложение установлено не в `/Applications` или `~/Applications`, укажите путь:

```sh
ANODHAS_HARNESS_APP="/path/to/DeepSeek Harness.app" ./Install.command
```

При переходе с прежних отдельных ANODHAS browser/computer plugins установщик остановится до изменения профиля. Прочитайте [миграцию](docs/MIGRATION.md), затем явно выполните:

```sh
./Install.command --migrate
```

Обновление того же пакета в стандартном каталоге поддержано без удаления. Конфликт неизвестного пакета или ссылки не перезаписывается. Прежний каталог пакета и точный backup двух файлов профиля сохраняются для восстановления; установщик не очищает пользовательские данные. Старую переподписанную копию Harness он не удаляет и не запускает. Не запускайте её параллельно с официальным клиентом на том же профиле.

`./Install.command --dry-run` проверяет выбранную версию и показывает план без установки. Это не заменяет последующую установочную проверку.

## Внешний Chrome

Установщик регистрирует native host `com.anodhas.browser_workspace`. Путь расширения выводится в конце установки и остаётся стабильным в каталоге плагина.

1. Откройте `chrome://extensions`, включите режим разработчика и загрузите указанную папку `chrome/extension`.
2. При обновлении прежнего расширения используйте его кнопку перезагрузки. Публичный ключ extension сохранён с 0.2.x, не устанавливайте вторую копию.
3. В popup Harness Use нажмите подключение. Harness должен работать.

Вкладки агента принадлежат конкретному чату, размещаются в отдельном фоновом окне и цветной группе 🤖. Личные вкладки нельзя подхватить инструментами плагина. Создание окна не запрашивает фокус; особенности поведения Chrome/оконной системы следует учитывать. Крестик карточки закрывает конкретную исходную вкладку, двойной клик явно раскрывает её. У каждого чата свои владение, refs и миниатюры. Картинка preview предназначена для наблюдения; агент управляет той же страницей браузерными инструментами.

## Обучение и маршруты

- `harness_use` сначала выбирает подходящий проверенный запрос; иначе открывает собственную страницу и начинает наблюдение нужной операции чтения.
- Для публичного обучения нужны два разных ввода через настоящую форму сайта. Поддержан HTTPS JSON GET с одним изменяемым path/query и небольшими верхнеуровневыми полями, одно из которых повторяет ввод. Это **не обучение любым сайтам и действиям**.
- Перед сохранением обе пробы повторяются без credentials и сверяются с наблюдением. Общий каталог содержит только проверенный публичный шаблон, не ответы/авторизацию.
- После изменения схемы агент возвращается к проверке через браузер. Новый проверенный контракт для той же страницы/полей заменяет прежний. Неподтверждённый результат не объявляется успешным, неоднозначные рецепты не выбираются наугад.
- Публичное повторное чтение работает без исходной страницы. Приватный YouTube replay использует работающий Chrome, но не открывает страницу и не использует кэш ответа.

### Авторизованное чтение YouTube

Поддержана только read-only операция меню текущего аккаунта: название канала и handle. В popup владелец явно разрешает session/background reading YouTube; дополнительные permissions не выдаются автоматически.

Первый путь: своя страница YouTube → `harness_use_youtube_observe` → видимое меню аккаунта → `harness_use_youtube_discover` → закрыть страницу. Затем `harness_use` с `intent=account-identity`, `input=current`, `fields=[name,handle]` сам выбирает единственный приватный рецепт этого чата.

Cookies и временная авторизация остаются в Chrome. В приватный рецепт входят минимальные параметры маршрута, версия клиента, выбранный аккаунт/числовые селекторы канала и отпечаток результата; ответы и токены не сохраняются. Приватные рецепты между чатами не передаются. Cookies Chrome при этом принадлежат общему профилю самого Chrome, а не изолированной cookie jar каждого чата. Изменение аккаунта требует проверки через страницу. Другие приватные API, произвольные POST и действия записи автоматически не обучаются.

### Консоль и сессия

`harness_use_console` выполняет JavaScript/DevTools в своей странице, не системный терминал. `harness_use_session_status` показывает метаданные cookies без значений. `harness_use_session_read` читает разрешённые поля same-origin GET текущей страницы. Консоль может менять состояние сайта, поэтому допустима только в границах поручения владельца. Page/console text остаётся недоверенным содержимым, не разрешением на новые действия.

## Память без бесконечного накопления

- Разовые сайты: 7 дней без успешного использования.
- Успешное использование в 3 разных дня за последние 30 дней: знакомый сайт, до 180 дней простоя.
- YouTube закреплён важным и не удаляется по возрасту. Настройки остальных important sites в UI пока нет.
- Очистка выполняется при обычной работе с реестрами, без отдельного фонового наблюдателя.
- Бюджет маршрутов 20 МиБ с резервом 256 КиБ для Chrome-private: до 936 публичных IDs + 64 приватных рецепта. 50 операций на сайт - мягкий ориентир статистики, не причина молчаливого удаления.
- Диагностический журнал очистки: до 10 МиБ и 7 дней. Private audit YouTube отдельно ограничен 100 событиями/32 КиБ внутри приватного бюджета. Полные страницы и ответы туда не складываются.
- Старые public cache-проекции истекают через сутки. Обычный shared replay не клонирует рецепт в каждый чат.
- При полном хранилище новая запись отклоняется; существующие полезные маршруты не удаляются молча. `harness_use_memory_status` показывает фактические размеры и сроки.

Эти бюджеты не ограничивают штатную историю чата Harness, журналы ОС или физический размер всей Chrome DB и не являются показателями RAM.

## Computer Use без переподписи Harness

Отдельный закреплённый MIT helper Cua `0.44.0` включён в ZIP и запускается лениво из плагина в direct/embedded mode. Не устанавливает и не запускает CuaDriver.app; не использует прежний carrier/host.json. На закрытие соединения получает EOF; принудительного завершения и фонового автозапуска нет.

`computer_status` проверяет наличие helper, `computer_permissions` читает фактические разрешения без показа запросов. Accessibility/Screen Recording при необходимости выдаёт сам владелец в System Settings. Наследование уже выданных разрешений не гарантируется: цепочка атрибуции зависит от запуска. Реальный статус следует проверить в своём Harness.

`computer_apps` → `computer_windows` → `computer_bind_window` привязывают конкретное существующее окно к чату. Далее доступны state/click/text/key/scroll и read-only live view. State выдаёт явные action_elements с точными адресами элементов; устаревшие адреса и ввод текста в не-редактируемые элементы отклоняются. После каждого действия нужен новый state и проверка результата. Режим только background window: без переключения Spaces, foreground fallback, запуска/закрытия приложений или shell/script-инструментов. Приложение может отвергнуть фоновый ввод; неизвестный исход не повторяется автоматически. Закрытие карточки освобождает привязку, не закрывает Mac-приложение.

## Проверки и ограничения

Проверены локальные механизмы владения, реальное расширение в тестовом Chromium, формы, снимки, preview/close, запрет чужих вкладок, приватное YouTube discover→save→close→fresh replay в рабочей среде, дедупликация и сроки с управляемыми часами. Переносимый helper отдельно прошёл initialize→permissions→EOF. См. [VALIDATION.md](VALIDATION.md).

В официальном Harness на Luna Off проверены снимок, ввод, нажатие, результат, мини-карточка и освобождение окна. В отдельном прогоне Chrome сохранил фокус во время ввода и нажатия в тестовой AppKit-форме. Это не гарантия для любого приложения. Полная установка на физически другом Mac требует отдельной приёмки. Это экспериментальный выпуск для macOS, проверенный на Apple Silicon; бинарник helper содержит arm64/x86_64, но полный Intel-сценарий отдельно не проверен. Другие версии Harness, Windows/Linux и каждый отдельный сайт не гарантируются. CAPTCHA, вход, trusted events и системные диалоги могут потребовать владельца. Правила доступа и подтверждения Harness сохраняются.

## Исходники и сборка

```sh
npm ci --ignore-scripts
npm run install:browser
npm test
npm run test:computer
npm run test:learning
npm run check
node scripts/fetch-runtime.cjs runtime
npm run build:installer
```

ZIP содержит Install.command, плагин, расширение и подписанный upstream helper с лицензиями. Официальное приложение Harness и личные данные в архив не входят. Исходники MIT; см. [NOTICE](NOTICE). Внешний Unbrowse, облачные браузеры и импорт cookies в сторонние сервисы не подключены.
