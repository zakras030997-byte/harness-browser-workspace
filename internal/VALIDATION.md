# Проверка native addon 0.1.0

10.11.2026 · macOS arm64 · Electron44.7.0 · Harness0.2.2-rc.1, build c59d10aff167ad7eefead4b3a9082fb57c8fbfe8.

Подтверждены четыре автоматических теста: same-origin cookies/скрытие значений, точное применение patch, маршрутизация чата и ответа без повторной доставки, ASAR overlay/readback без изменения исходного архива.

Изолированный E2E использует настоящий Electron44.7.0, исходный DesktopBrowserGuests из установленного Harness, patched preload и полный путь вызова нового инструмента через клиент/очередь к webview. Проверены 20 инструментов в каталоге, две вкладки, ввод, доверенное мышиное нажатие, снимок, JavaScript без Node, чтение/установка/удаление фиктивных HttpOnly cookies, запрет чужого tabId и смены чата, закрытие одной вкладки с сохранением соседней. Это native интеграционный стенд, а не снимок личного аккаунта.

Отдельная копия полного приложения подготовлена и локально подписана. Исходный архив приложения не изменён; изменены только два main/preload файла и добавлен модуль управления в копии. Проверка подписи и ASAR readback прошла.

Глобальная регистрация в рабочем desktop-профиле выполнена после подтверждённого закрытия владельцем. Сохранены резервные копии, проверено отсутствие изменений остальных строк профиля и зависимостей. Копия приложения запущена с прежними чатами. В настоящем окне агент подтвердил native bridge и создал две штатные вкладки. Первый тест выявил ошибочное открытие sidebar:// через ресурсный API; исправлено. Второй показал фактически выбранную вкладку при ложной ошибке подтверждения на устаревшем DOM-узле; исправлено через штатное состояние панели и свежий DOM. Явное restore=true восстанавливает сохранённую страницу, готовность guest подтверждается read-only запросом.

**Финальная проверка моделью в установленном Harness прошла:** сохранённая вкладка выбрана и восстановлена; поле заполнено HARNESS_NATIVE_BROWSER_OK; кнопка нажата; новый snapshot подтвердил «Получено: HARNESS_NATIVE_BROWSER_OK». Выполнено движение указателя; снимок получен как нативное durable image attachment в чате. Прочитана только фиктивная HttpOnly cookie локального сайта, собственная HttpOnly cookie создана, проверена и удалена. Вторая тестовая вкладка закрыта, первая оставлена выбранной. Финальный маркер HARNESS_NATIVE_PANEL_OK сверён с успешными tool/result; отсутствие ошибок и наличие durable image проверены отдельно. AX-снимок настоящего окна подтвердил выбранную вкладку, значение поля и текст результата. Полный оконный screenshot CUA недоступен из-за ошибки ScreenCaptureKit; page screenshot через сам плагин работает.

Снимки переводятся через штатный Attachment Store; MCP wire block не используется как внутренний формат LLM. Проверка не меняла модель и остальные чаты. Одноразовый host-hook Session Controller после завершения снят; фоновых тестов/расписаний нет. В одном промежуточном запуске была открыта исходная копия без моста: модельный запрос тогда не отправлялся. После перехода на подготовленную копию выполнена ровно одна финальная проверка через SDK. Исходная копия приложения сохранена.


Другие сборки и ОС, загрузки файлов, нативные системные диалоги, междоменные iframe, CAPTCHA и все сайты не проверены. Значения личных cookies не читались. На GitHub этот addon не публиковался.
